# Improvement Deep-Dive — omarchy-nym-vpn — 2026-10-21

## Top recommendations (ranked, with effort S/M/L)
1. **Strict SOCKS5 address validation in `status.py:socks5()`** — currently only checks `":" in addr` before passing it to `nym-vpnc socks5 enable --socks5-address`. Validate properly: split host/port, `ipaddress.ip_address(host)` (or `localhost`), port `1–65535`; reject non-loopback binds unless an explicit `--allow-lan` flag is passed (a 0.0.0.0 SOCKS5 listener on a VPN box is an open relay). Same hardening for `dns_op()` whose regex `^[0-9a-fA-F.,:\s]+$` accepts garbage like `...`. [S]
2. **Enforce the vendored-binary checksum in CI**: THIRD_PARTY_NOTICES.md documents `bin/nym-vpnc` = upstream `nym-vpnc_2026.12.4_amd64.deb`, SHA-256 `983d472c...39bfd30` — but nothing re-verifies it. Add a CI job + `verify-bin.sh` that recomputes the hash so a tampered/corrupted binary fails loudly. (Checksum-pin is the right choice here; build-from-source of the Rust nym-vpn-client is a heavy alternative — offer it as an optional documented path for the paranoid, not the default.) [S]
3. **Unit-test the parsers**: `parse_*` functions are pure text→dict — ship fixture outputs from nym-vpnc v2026.12.4 and run them in CI. Parser drift vs daemon output is this repo's #1 breakage mode (formats 'verified against v2026.12.4 / daemon v2026.13.0' per comment — make that checkable). [M]
4. **Track upstream nym-vpn-client releases**: cron CI that polls the upstream releases API and opens an issue when a new `nym-vpn-v*` tag appears (vendored CLI will silently age). [S]
